# PharmaStock

PharmaStock is a full-stack pharmacy inventory management application designed for neighbourhood pharmacies.

It manages medicine batches, tracks expiry dates, supports FEFO (First Expiry, First Out) dispensing, provides expiry alerts, imports messy batch data, and generates reorder notifications when stock falls below a configured threshold.

## Problem

Pharmacies often manage the same medicine across multiple batches with different expiry dates.

A simple total-stock count is not enough because:

- expired medicines must never be dispensed
- the earliest-expiring valid batch should be used first
- staff need visibility into upcoming expiries
- low stock should trigger a reorder notification
- imported inventory data can contain inconsistent formats

PharmaStock addresses these problems through batch-level inventory management.

## Key Features

### Authentication
- User registration
- Secure password hashing with bcrypt
- JWT-based login authentication

### Medicine Management
- Create medicines
- View medicine details
- Update reorder thresholds
- Search medicines
- Pagination
- Sorting

### Batch Management
- Add medicine batches
- Track batch number
- Track quantity
- Track expiry date
- Quarantine expired batches

### FEFO Dispensing

When stock is dispensed, PharmaStock selects the valid batch with the earliest expiry date first.

Expired and quarantined batches are never used for dispensing.

### Expiry Automation

`POST /api/clock` simulates the daily inventory job.

It:

1. Identifies expired batches.
2. Quarantines them.
3. Finds batches expiring within seven days.
4. Returns a report.

### Messy Batch Import

The import endpoint handles:

- null values
- quantities such as `"10 units"`
- `dd/mm/yyyy` dates
- ISO dates
- duplicate rows
- invalid rows

The endpoint returns:

- imported
- deduped
- rejected
- rejected rows

### Reorder Notification

Each medicine has a reorder threshold.

When dispensing causes in-date stock to fall below the threshold, PharmaStock creates a `REORDER_ALERT` event in the outbox.

The outbox represents the Notification Service integration boundary.

Example FEFO Flow

Suppose a medicine has:

Batch A → 20 units → expires 2026-10-01
Batch B → 30 units → expires 2026-11-01
Batch C → 40 units → expires 2027-01-01

Dispensing 25 units results in:

Batch A → 0
Batch B → 25
Batch C → 40

The earliest valid expiry is consumed first.
